# BOM-WMS 多数据源整合方案

## Context（为什么做这个变更）

BOM-WMS 项目当前数据源硬编码为 H2 内存库（开发兜底）+ MySQL 8.0.33（生产），且 `MybatisPlusConfig` 的 `DbType` 硬编码为 `MYSQL`，`DataInitializer` 的 DDL 也是 MySQL/H2 混合语法。用户希望保留 MySQL 为主，新增 SQLite 和 PostgreSQL 作为**可选数据源**，通过 Spring profile 切换，以适配不同部署场景（SQLite 适合单机便携、PG 适合已有 PG 栈的用户）。

**关键前提**（来自代码审查）：
- `MybatisPlusMetaObjectHandler` 已自动填充 `createTime`/`updateTime`/`delFlag`，DDL 中的 `ON UPDATE CURRENT_TIMESTAMP` 可删除
- 所有实体类的 JSON 字段（`specAttributes`/`snapshot`/`detail`/`sourceSummary`）均为 `String` 类型，无 JSON TypeHandler，可用 `TEXT` 替代 `JSON`/`CLOB`
- `init.sql` 未被代码引用（仅作 MySQL 手动建库参考），`DataInitializer` 用 `jdbcTemplate.execute()` 自带 H2 兼容 DDL

## 实施步骤

### Step 1：pom.xml 新增驱动依赖
在 `h2` 依赖之后新增（`scope=runtime`，放在现有依赖末尾以遵守 import 顺序铁律）：
- `org.xerial:sqlite-jdbc:3.45.1.0`（runtime）
- `org.postgresql:postgresql`（不写 version，由 Spring Boot 3.2.12 parent 管理）

### Step 2：Profile 配置拆分
**改造 `application.yml`**：移除 `spring.datasource` 与 `spring.h2.console`，新增 `spring.profiles.active: h2` 与 `bom-wms.db-type: h2` 作为默认值，保留 mybatis-plus/jwt/springdoc/logging 等公共配置。

**新增 4 份 profile 文件**（`src/main/resources/`）：
| 文件 | db-type | datasource.url | driver |
|---|---|---|---|
| `application-h2.yml` | h2 | `jdbc:h2:mem:bom_wms;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE` | `org.h2.Driver` |
| `application-mysql.yml` | mysql | `jdbc:mysql://localhost:3306/bom_wms?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8` | `com.mysql.cj.jdbc.Driver` |
| `application-sqlite.yml` | sqlite | `jdbc:sqlite:./data/bom-wms.db` | `org.sqlite.JDBC` |
| `application-pgsql.yml` | postgresql | `jdbc:postgresql://localhost:5432/bom_wms` | `org.postgresql.Driver` |

每份含 `spring.datasource`（url/username/password/driver-class-name）+ `bom-wms.db-type`。`application-h2.yml` 额外开启 `spring.h2.console`。

### Step 3：DbType 动态化
**新建 `DatabaseTypeResolver.java`**（`cn.aicoa.wms.config`）：
- `@Component`，`@Slf4j`
- `@Value("${bom-wms.db-type:h2}")` 读取配置
- 暴露 `getDbType()` 返回 MyBatis-Plus `DbType`（h2→`DbType.H2`，mysql→`MYSQL`，sqlite→`SQLITE`，postgresql→`POSTGRE_SQL`）
- 暴露 `getDbTypeKey()` 返回原始字符串（如 `"sqlite"`），供 DataInitializer 加载对应脚本

**改造 `MybatisPlusConfig.java`**：
- 注入 `DatabaseTypeResolver`
- `new PaginationInnerInterceptor(resolver.getDbType())` 替换硬编码 `DbType.MYSQL`
- 新增 import：`cn.aicoa.wms.config.DatabaseTypeResolver`（放在 import 末尾）

### Step 4：DDL 脚本拆分（方案 B：独立 SQL 文件）
**采用方案 B**：抽取 DDL 到独立 SQL 脚本，按 `bom-wms.db-type` 加载。理由：DataInitializer 当前已 400+ 行，三套 DDL 内嵌会让单类膨胀到 1500+ 行不可维护。

**`schema/` 目录文件组织**：
| 文件 | 用途 |
|---|---|
| `schema/init-h2.sql` | H2 DDL（从 DataInitializer 现有 DDL 抽取，保留 `CLOB`/`AUTO_INCREMENT`） |
| `schema/init-mysql.sql` | MySQL DDL（现 `init.sql` 改名，保留 `JSON`/`LONGTEXT`/`ENGINE=InnoDB`） |
| `schema/init-sqlite.sql` | SQLite DDL（新写，见下方语法适配） |
| `schema/init-pgsql.sql` | PostgreSQL DDL（新写，见下方语法适配） |

**DDL 语法适配规则**：

| 障碍 | MySQL | H2 | SQLite | PostgreSQL |
|---|---|---|---|---|
| 自增主键 | `BIGINT AUTO_INCREMENT` | `BIGINT AUTO_INCREMENT` | `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |
| 大文本 | `LONGTEXT`/`TEXT` | `CLOB` | `TEXT` | `TEXT` |
| JSON 字段 | `JSON` | `CLOB` | `TEXT` | `TEXT` |
| TINYINT | `TINYINT` | `TINYINT` | `INTEGER` | `SMALLINT` |
| ON UPDATE CURRENT_TIMESTAMP | 保留 | 保留 | 删除（靠 MetaObjectHandler） | 删除 |
| UNIQUE 子句 | `UNIQUE KEY uk_x(col)` | 列级 `UNIQUE` | 列级 `UNIQUE` | `CONSTRAINT uk_x UNIQUE(col)` |
| ENGINE=InnoDB CHARSET= | 保留 | 删除 | 删除 | 删除 |
| CHECK / INDEX IF NOT EXISTS / DEFAULT CURRENT_TIMESTAMP | 全兼容，不变 | | | |

### Step 5：DataInitializer 改造
**改造 `DataInitializer.java`**：
- 注入 `DatabaseTypeResolver`
- `createTables()` 方法改为：用 Hutool `ResourceUtil.readUtf8Str("schema/init-" + resolver.getDbTypeKey() + ".sql")` 读取脚本，按 `;` 切分（跳过空行和注释行），逐条 `jdbcTemplate.execute()`
- 保留现有 `initAccounts()/initMaterialCategory()/initMaterial()/initLocation()/initInventory()/initSupplier()` 不动（INSERT 语句为标准 SQL，四库通用）
- 保留 `createIndexIfNotExists()` 私有方法（已被各脚本内联使用，可删除或保留为兜底）
- 新增 import：`cn.hutool.core.io.ResourceUtil`、`cn.hutool.core.util.StrUtil`、`cn.aicoa.wms.config.DatabaseTypeResolver`（放在 import 末尾）

**注意**：SQLite 不支持 `CREATE INDEX IF NOT EXISTS` 的 `UNIQUE` 前缀写法，需在脚本内用 `CREATE UNIQUE INDEX IF NOT EXISTS`。

### Step 6：删除旧 init.sql
将 `schema/init.sql` 重命名为 `schema/init-mysql.sql`（内容保持 MySQL 专属语法，作为 MySQL 手动建库参考）。旧 `init.sql` 不再保留。

### Step 7：文档更新
1. **`.trae/rules/项目约束.md`**：第 10 条追加「SQLite 3.45+ / PostgreSQL 14+ 为可选数据源，通过 Spring profile 切换」
2. **`README.md`**：
   - 5.1 环境要求表新增 SQLite/PG 行（标注"可选"）
   - 5.2 后端启动增加 profile 切换说明
3. **`docs/数据库设计.md`**：新增"多数据库支持"章节，说明四脚本路径与语法差异
4. **`docs/部署指南.md`**：新增 SQLite/PG profile 启动命令与初始化说明
5. **`task_plan.md`**：追加 v1.2.0 子任务与修订日志
6. **`progress.md`**：记录本次实施

## 验证方案

### 自动化验证（用户手动执行）
```bash
# 1. 编译验证
cd d:\Projects\wms\wms-web
mvn clean compile

# 2. 单元测试（默认 H2 profile，回归验证现有测试不破坏）
mvn test

# 3. SQLite profile 启动验证（无需安装，文件库）
mvn spring-boot:run -Dspring-boot.run.profiles=sqlite
# 验证后访问 http://localhost:8080/swagger-ui.html，调用 /api/material/list 确认数据

# 4. MySQL profile 启动验证（需本地 MySQL，先执行 init-mysql.sql 建库）
mvn spring-boot:run -Dspring-boot.run.profiles=mysql

# 5. PG profile 启动验证（需本地 PG，先建库 bom_wms，再执行 init-pgsql.sql）
mvn spring-boot:run -Dspring-boot.run.profiles=pgsql
```

### 重点验证项
| 验证点 | SQLite | PG | MySQL | H2 |
|---|---|---|---|---|
| 自增主键回填 | `INTEGER PRIMARY KEY AUTOINCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` | `AUTO_INCREMENT` | `AUTO_INCREMENT` |
| TINYINT 字段读写（status/is_admin/del_flag） | 用 INTEGER | 用 SMALLINT | TINYINT | TINYINT |
| JSON 字段（spec_attributes/snapshot/detail/source_summary）String 序列化 | TEXT | TEXT | JSON | CLOB |
| 分页 SQL 正确性 | `LIMIT ? OFFSET ?` | `LIMIT ? OFFSET ?` | `LIMIT ?, ?` | `LIMIT ? OFFSET ?` |
| 现有 20 个单元测试通过 | ✅ | ✅ | ✅ | ✅（回归） |

### 切换 profile 的命令示例
```bash
# 打包后切换
java -jar target/bom-wms-1.1.0.jar --spring.profiles.active=sqlite
java -jar target/bom-wms-1.1.0.jar --spring.profiles.active=pgsql
java -jar target/bom-wms-1.1.0.jar --spring.profiles.active=mysql

# 或通过环境变量
set SPRING_PROFILES_ACTIVE=sqlite
java -jar target/bom-wms-1.1.0.jar
```
